# dsh-locale-ru

[![self-check](https://github.com/execrat1on/dsh-locale-ru/actions/workflows/test.yml/badge.svg)](https://github.com/execrat1on/dsh-locale-ru/actions/workflows/test.yml)
[![license: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](./LICENSE)

Русский язык для веб-интерфейса **DeepSeek Harness**: **57 namespace'ов, 2588 строк** —
переведено всё, что Harness отдаёт через словари локализации, от чата и траектории до
настроек, планировщика и плагинов.

Пакет ничего не рисует и не занимает ни одного слота: он только регистрирует язык `ru`
и по одному словарю на namespace. Чего в переводе нет, то показывается по-английски —
сырые ключи в интерфейсе не появляются.

## Как включить

* **Автоматически** — если браузер просит русский (`navigator.languages` содержит `ru`),
  интерфейс переключится сам при следующем запуске Harness.
* **Вручную** — Settings → General → *Language* → «Русский». Сохранённый выбор имеет
  приоритет: если у вас явно выставлен английский, автоподбор не сработает, переключите
  язык руками.

## Установка

Требования: DSH `>= 0.2.0-rc.2`, Node.js `>= 20`.

**Через менеджер плагинов.** Settings → Plugins → установка бандла, источник `GitHub`,
репозиторий `execrat1on/dsh-locale-ru`. Клонирование делает `git`, поэтому он должен быть
доступен в `PATH`.

**Из tarball (если git недоступен).**

```powershell
git clone https://github.com/execrat1on/dsh-locale-ru.git   # или скачайте архив и распакуйте
cd dsh-locale-ru
npm pack                                                    # получится dsh-locale-ru-1.0.0.tgz
```

Затем установите бандл из полученного `.tgz` (абсолютным путём) — tarball удалять нельзя,
профиль ссылается на него.

**Перезапуск.** После установки перезапустите Harness: список клиентских модулей и манифест
читаются на старте.

> **Не ставьте вместе с `awesome-dsh-plugins`.** В нём уже встроена копия этого же
> перевода: обе половины зарегистрируют `ru` и одни и те же словари. Плагин это
> переживёт — повторная регистрация языка ловится и уходит в `console.warn`, словари
> регистрируются поверх, — но держать две копии незачем. Либо `dsh-locale-ru`, либо
> встроенный пакет.

## Что переводится

Переводится весь текст, который Harness отдаёт через словари локализации: `common`,
`chat`, `conversation`, `trajectory`, `workspace`, `settings*`, `pluginManager`,
`sidebar*`, `command`, `shortcut*`, `model`, `plan`, `goal`, `job`, `subagent`,
`schedule*`, `deliverable*`, `voice-input`, `agent-team` и остальные namespace'ы
клиентских плагинов.

Крупнейшие словари:

| Namespace | Строк |
|---|---|
| `conversation` | 363 |
| `trajectory` | 192 |
| `schedule.manager` | 187 |
| `chat` | 186 |
| `pluginManager` | 186 |
| `settings.models` | 113 |
| `workspace` | 111 |
| `voice-input` | 101 |

Не переводятся (и это правильно): названия брендов (DeepSeek Harness, DSH), имена команд
(`/plan`, `/model`), пути, идентификаторы, названия моделей и технические значения вроде
`UTC`.

## Как это работает

| Файл | Назначение |
|---|---|
| `client.template.js` | Оболочка браузерной половины с маркерами `__RU_LOCALE__` и `__RU_PACK__` |
| `ru/pack.source.js` | Установщик: `addLanguage('ru')` + `register(namespace, 'ru', …)`, защищён от повторной регистрации |
| `ru/ru.json` | Собранный словарь `{ "<namespace>": { "<key>": "…" } }` |
| `ru/parts/*.json` | 16 частей перевода — источники сборки, их удобно читать и ревьюить |
| `schema/keys.en.json` | Какие namespace'ы и ключи есть в DSH и какие плейсхолдеры использует каждый; `null` — у строки пустой исходник |
| `build.mjs` | Собирает `client.js`, вшивая словарь и установщик в шаблон, и проверяет синтаксис |
| `client.js` | Готовый артефакт: `window.__ModuleLoader__.load({ id: 'dsh-locale-ru', … })` |
| `index.js` | Хост-половина: не регистрирует ничего, существует ради строки бандла |
| `tools/assemble.mjs` | Сливает части в `ru/ru.json` и валидирует по схеме |

В браузер ничего не догружается: словарь вшит в `client.js` (134 KiB), ни `fetch`, ни
одного URL в бандле нет.

**Английские тексты в репозитории не публикуются.** В `schema/keys.en.json` лежат только
имена ключей и наборы плейсхолдеров (например `chat :: message.stepProcess.sharedPrefix →
""` или `common :: key → "{name}|{count}"`). Этого достаточно, чтобы поймать потерянный
плейсхолдер и увидеть, что новый ключ DSH остался без перевода, — и не нужно копировать
чужой интерфейсный текст.

## Обновление, когда DSH добавляет строки

```powershell
npm run assemble     # части -> ru/ru.json, с проверкой по schema/keys.en.json
npm run build        # ru/ru.json -> client.js
npm test             # 120+ проверок, включая запуск настоящего LocaleRuntime
```

`assemble` падает с ненулевым кодом, если namespace или ключ потерялся, перевод пустой,
плейсхолдер пропал или в значение просочилась CJK. Значения, которые выглядят
непереведёнными, печатаются как предупреждения.

Когда в DSH появляется новый ключ, `schema/keys.en.json` нужно обновить: добавьте ключ в
соответствующий namespace (сигнатура — плейсхолдеры через `|`, либо `null` для пустого
исходника). Дальше `npm run assemble` скажет, чего не хватает.

## Разработка

```bash
npm run build     # client.js из шаблона, словаря и установщика
npm run assemble  # ru/ru.json из ru/parts
npm test          # test/verify.mjs + test/dsh-runtime.mjs
```

`test/verify.mjs` не требует ни фреймворка, ни сети: словарь, схема (в том числе «в схеме
нет английского текста»), воспроизводимость `ru/parts → ru/ru.json`, регистрация всех 57
словарей, корректный dispose, устойчивость к повторной регистрации, отсутствие сети в
бандле и поля манифеста.

`test/dsh-runtime.mjs` загружает **настоящий** бандл `@deepseek-ai/dsh-client-locale` в
`vm`-песочницу и прогоняет через него этот пакет: до установки браузер с `ru-RU` получает
английский, после — русский, и все 2588 ключей разрешаются в свои значения. Путь к DSH
ищется сам (аргумент, `DSH_ROOT`, локальные установки); если DSH рядом нет, тест
сообщает о пропуске и выходит с кодом 0 — поэтому CI без DSH остаётся зелёным.
